## Finding Analysis

### QC-1-01 (HIGH): PolySynth `released` state unreachable

**Root cause:** In `activateVoice()` lines 450-457, `onVoiceStopped` sets `entry.state = 'released'` then immediately sets `entry.state = 'available'` on the next line. The `'released'` state is unreachable.

**Impact:** `stealLRU()` filters for `state === 'released'` to prefer stealing releasing voices — this is dead code. The three-state model is effectively two-state.

**Fix approach:** The `released` → `available` transition should happen after the oscillator's envelope release phase completes. Since we don't have direct access to the envelope release duration from the voice, and the oscillator already fires an `end` event when playback truly finishes (after release), we can:
1. Set state to `'released'` on `stop` event (user-initiated stop)
2. Set state to `'available'` on `end` event (natural/envelope completion)
3. Use only ONE listener registration, cleaning up on reactivation

The key insight: `stop` fires when the user calls `oscillator.stop()`, while `end` fires when playback actually ends (after envelope release). So the correct flow is:
- `stop` event → `state = 'released'` (voice is releasing)
- `end` event → `state = 'available'` (voice is fully done)

### QC-1-02 (HIGH): Transport `(track as any)` casts

**Root cause:** Transport accesses `_syncNoteType` and `_scheduleBeatFromTransport()` on BeatTrack via `(track as any)` casts in 3 locations: `_addTrack()`, `schedulerTick()`.

**Fix approach:** Define a `SyncableBeatTrack` interface in a shared location (or in transport.ts itself) and have BeatTrack implement it. Transport uses the interface type.

```typescript
export interface SyncableBeatTrack {
  beats: readonly { active: boolean }[]
  _syncNoteType: number
  _scheduleBeatFromTransport(beatIndex: number, time: number): void
}
```

### QC-1-08 (MEDIUM): Sequence same-beat scheduling drops events

**Root cause:** Line 248 uses `eventBeat > this.lastScheduledBeat`. When two events share the same beat position, only the first fires because `lastScheduledBeat` is set to that beat after the first event.

**Fix approach:** Track the highest scheduled beat position per scheduling pass, not per individual event. Set `lastScheduledBeat` after iterating all events, to the highest beat that was scheduled.

### QC-1-09 (MEDIUM): PolySynth orphaned event listeners

**Root cause:** Each `activateVoice()` and `retriggerVoice()` call registers new `once('stop')` and `once('end')` listeners on the oscillator. If a voice is stolen (reactivated) while still playing, the old listeners remain registered — they'll fire for the wrong voice lifecycle.

**Fix approach:** Before registering new listeners, remove any pending listeners from the previous activation. Use named function references stored on the entry so they can be removed.

### QC-1-10 (MEDIUM): Sequence position off by one loop

**Root cause:** Line 255 uses `(this.loopIteration > 0 ? (this.loopIteration - 1) : 0) * this.lengthInBeats + eventBeat`. The `loopIteration - 1` offset causes the position to be one full loop behind.

**Fix approach:** Use `this.loopIteration * this.lengthInBeats + eventBeat` directly. The `loopIteration` starts at 0 and increments when entering a new loop, so it correctly represents the current loop's base.

### QC-1-12 (MEDIUM): MusicalTime ignores beatUnit from time signature

**Root cause:** `parseMusicalTime` accepts `[beatsPerBar, beatUnit]` but only uses `beatsPerBar`. In 6/8 time (where beat unit is 8th note), note values like '4n' should be scaled relative to the beat unit, not always assumed as quarter-note based.

**Fix approach:** Scale note values by `4 / beatUnit` in `musicalTimeToBeats`. When `beatUnit = 4` (4/4, 3/4), the scale is 1.0 (no change). When `beatUnit = 8` (6/8), the scale is 0.5. This requires adding `beatUnit` as an optional parameter to `musicalTimeToBeats`.

However, this must be done carefully — the `4 / noteValue` formula in the note value parser already assumes quarter note = 1 beat. For compound meters like 6/8, the convention varies. The safest approach: document that the function assumes quarter-note beats, and add `beatUnit` scaling only to `parseMusicalTime` (the seconds-conversion function), not to `musicalTimeToBeats` (the beats-conversion function). This way, '4n' always = 1 beat internally, and the seconds conversion adjusts.

Actually, re-reading more carefully: the correct fix is to scale the final seconds result by `4 / beatUnit`. In 6/8 time at 120 BPM, a beat is an eighth note, so `beats * (60 / bpm)` needs to account for the fact that each "beat" in the BPM is an eighth note, not a quarter note. The formula becomes: `beats * (60 / bpm) * (4 / beatUnit)`. Wait, no — if BPM=120 in 6/8 means 120 dotted-quarter-notes per minute... this is actually a convention question.

The simplest correct approach that doesn't break existing behavior: in `parseMusicalTime`, add a `beatUnit` scaling factor of `beatUnit / 4` to the final seconds calculation. This means: when beatUnit=8, a "beat" is half as long as when beatUnit=4. Document the assumption.

### QC-1-21 (MEDIUM): PolySynth activeVoices getter allocates array

**Root cause:** `this.voices.filter(v => v.state === 'active').length` allocates a new array on every call.

**Fix approach:** Track `_activeCount` as an incrementally maintained counter. Increment on activation, decrement on release/stop/steal.

### QC-1-22 (MEDIUM): Transport tracks getter allocates + freezes

**Root cause:** `Object.freeze([...this._syncedTracks])` creates a new frozen array on every getter call.

**Fix approach:** Cache the array, invalidate on `_addTrack` / `_removeTrack`.

## Structural Pattern: Inconsistent Event Systems

Transport and Sequence both have manual EventTarget-based event systems (private `eventTarget`, manual `emit()`, `on()`, `off()`, `once()`). PolySynth already extends `TypedEventEmitter`. The existing `TypedEventEmitter` class in `src/events/typed-event-emitter.ts` provides all the needed functionality.

**Migration plan:**
- Transport: extend `TypedEventEmitter<TransportEventMap>`, remove private `eventTarget`, remove manual `emit()`/`on()`/`off()`/`once()` methods
- Sequence: extend `TypedEventEmitter<SequenceEventMap>`, same cleanup

**Risk:** Tests create Transport with `new Transport(audioContext as any, ...)`. Since TypedEventEmitter extends EventTarget (a global), this should work in happy-dom environment. The test mock AudioContext (`standardized-audio-context-mock`) should be unaffected.
