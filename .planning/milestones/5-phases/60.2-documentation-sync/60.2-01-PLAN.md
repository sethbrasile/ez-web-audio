<task id="3">
<title>Fix multiple-contexts guide sinkId example</title>
<description>
In docs/guide/multiple-contexts.md:

1. Change the "Full Example: Monitoring Output" sinkId example to use `ctx.setSinkId()` instead of passing sinkId to the AudioContext constructor. The constructor option has limited browser support; setSinkId() is the recommended approach. Update the code from:
   ```typescript
   const monitorCtx = new AudioContext({ sinkId: 'headphone-device-id' })
   ```
   to:
   ```typescript
   const monitorCtx = new AudioContext()
   await monitorCtx.setSinkId('headphone-device-id')
   ```

2. Verify the factory function reference table includes all M5 factories. It currently does — confirm createLFO is present (it creates synchronously, not async). Add createSequence if missing.
</description>
</task>

<task id="4">
<title>Fix Howler manifest example alignment in audio-sprite docs</title>
<description>
In docs/examples/audio-sprite.md:

The Howler example (line ~60-68) shows `"explosion": [1000, 2500]` which means offset=1000ms, duration=2500ms (so end=3500ms). But the audiosprite example above shows `"explosion": { "start": 1.0, "end": 2.5 }` which is 1500ms duration.

Fix the Howler example to match: `"explosion": [1000, 1500]` so both represent the same time range (1.0s to 2.5s).

Similarly verify "laser" is consistent: audiosprite has start=0, end=0.3 (300ms duration). Howler has [0, 300] = offset 0, duration 300ms. This is correct.
</description>
</task>
