    ```typescript
      length: MusicalTimeNotation

      loop?: boolean

      events?: Array<{

      _scheduleEventsInWindow(

      on<K extends keyof SequenceEventMap>(type: K, listener: (event: SequenceEventMap[K]) => void): this { ... }

      once<K extends keyof SequenceEventMap>(type: K, listener: (event: SequenceEventMap[K]) => void): this { ... }

      dispose(): void { ... }
    }
    ```

    **Key implementation details for `_scheduleEventsInWindow`:**

    This is the critical method. On each call from Transport.schedulerTick():

    1. Convert the lookahead window from seconds to beats:
       `beatWindow = lookahead * (bpm / 60)`

    2. Calculate current beat position in sequence:
       `elapsedSeconds = currentTime - transportStartTime`
       `elapsedBeats = elapsedSeconds * (bpm / 60)`
       `sequenceBeats = elapsedBeats % lengthInBeats` (if looping)

    3. Calculate end of window in beats:
       `windowEndBeats = sequenceBeats + beatWindow`

    4. For each event with beats in [scheduledUpTo, windowEndBeats):
       - Calculate the exact AudioContext time for this event
       - Call `callback(exactTime, position)` where position is derived from beat position
       - Emit 'event' CustomEvent

    5. Handle loop boundary: if windowEndBeats > lengthInBeats and loop is true:
       - Emit 'loop' event
       - Wrap and check events in [0, windowEndBeats - lengthInBeats)

    6. For loop: false — once all events in a single pass have fired, stop scheduling.

    **IMPORTANT BPM consideration:** Do NOT pre-compute seconds for events. Store as beats.
    Convert beat→seconds at scheduling time using the `bpm` parameter passed from Transport.
    This is how live BPM changes work: Transport passes current BPM each tick.
