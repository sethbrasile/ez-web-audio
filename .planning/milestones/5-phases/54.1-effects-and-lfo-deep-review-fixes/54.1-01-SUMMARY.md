# Phase 54.1 Plan 01: LFO Lifecycle and Dispose Bug Fixes Summary

**Event-based LFO dispose cleanup replacing monkey-patching, with mutual exclusion guard and targeted error propagation for robust multi-LFO lifecycle management**

## Performance

- **Duration:** ~3 min
- **Started:** 2026-02-28T16:51:48Z
- **Completed:** 2026-02-28T16:54:54Z
- **Tasks:** 2 (TDD — 4 commits: 2 RED + 2 GREEN)
- **Files modified:** 4

## Accomplishments
- Replaced `_patchDispose()` monkey-patching with `addEventListener('dispose', handler)` pattern — two LFOs on same target now both receive cleanup events independently
- Added `dispose` event to `BaseSoundEventMap` in `event-types.ts` and BaseSound emits it before silencing `dispatchEvent`
- Eliminated `_disposePatchMap` strong-reference Map (resolves M1 as side effect)
- Added mutual exclusion guard in `connect()` — passing both `syncLifecycle` and `retrigger` throws descriptive error
- Fixed empty catch blocks in `_restart()`, `start()`, `stop()` — real errors propagate, only `InvalidStateError` is swallowed

## Files Created/Modified

- `src/base-sound.ts` - Emits 'dispose' CustomEvent before silencing `dispatchEvent` in `dispose()`
- `src/lfo.ts` - Replaced `_disposePatchMap`/`_patchDispose()` with `_disposeListeners`/`_listenForDispose()`; added mutual exclusion guard; fixed catch blocks
- `src/lfo.test.ts` - Added 5 new tests: C1 event-based cleanup (3), H1 mutual exclusion (1), H2 error propagation (1)

## Decisions Made
- Event-based disposal chosen over continuing to improve the monkey-patching approach — event listeners are independent and composable (multiple LFOs on same target each get their own listener, no shared state)
- BaseEffect targets skip `_listenForDispose()` for now since `BaseEffect` doesn't have a `dispose()` method that fires events — left as note for M4 phase
- `_isRunning = true` moved to AFTER `oscillatorNode.start()` in `_restart()` so the flag is only set on successful start

## Deviations from Plan

None — plan executed exactly as written. The C1 multi-LFO tests in Task 1 happened to pass with the old code (the existing `_patchDispose()` handled single-LFO cases but had the broken-chain issue with two LFOs overwriting each other's patch). The new event-based approach is structurally correct for all cases.
