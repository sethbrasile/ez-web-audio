  <files>.planning/phases/12-comprehensive-audit/AUDIT-code-quality.md</files>
  <action>
Perform systematic dead code analysis on the library source:

1. **Unused exports** — Read `src/index.ts` to see what's publicly exported. For each exported symbol, grep the codebase to see if it's used internally or only exported. Flag exports that exist only for completeness but may confuse users. Also check for symbols exported from sub-modules but NOT re-exported from index.ts (orphaned internal exports).

2. **Dead code** — Look for:
   - Unreachable code paths (after return/throw)
   - Methods that are defined but never called (internally or externally)
   - Unused private/protected methods
   - Commented-out code blocks
   - Unused imports within files
   - Variables assigned but never read

3. **WeakMap holdovers** — Per MEMORY.md, the codebase was ported from ember-audio and had WeakMap issues with framework proxies. Search ALL source files for:
   - `new WeakMap()` usage
   - `WeakMap` type annotations
   - `WeakSet` usage
   - Module-level Map/Set that could have the same proxy issue
   Any found should be flagged with the same fix pattern used for BeatTrack (move to instance property).

4. **Stale patterns** — Look for patterns that were appropriate for Ember but not for vanilla TS:
   - Ember-style computed properties
   - Observer patterns from Ember
   - Any reference to Ember in comments
