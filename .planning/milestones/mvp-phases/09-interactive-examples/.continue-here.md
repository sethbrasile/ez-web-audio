### GLOBAL: Remove "Browser Audio Requirement" warnings from ALL examples
**Severity:** UX
**Rationale:** Every example requires a click/tap to interact in the first place, so the warning serves no purpose. Remove the warning from all 9 example markdown pages AND from any component templates that show it.

**Severity:** Critical — completely non-functional
**Symptom:** The whole thing is unavailable, clicking does nothing.
**Component:** `docs/.vitepress/theme/components/DrumMachine.vue`
**Likely causes to investigate:**
- Initialization logic may be failing silently (check error handling)
- BeatTrack API may not match what the component expects
- Check if `createBeatTrack` is being called correctly
- Check browser console for errors

### 2. Synth Keyboard (09-02) — Layout Bug
**Severity:** Medium
**Symptom:** When you click a key, the keyboard shoots downward because the note name appears above it and pushes content down.
**Component:** `docs/.vitepress/theme/components/SynthKeyboard.vue`
**Fix:** The container for the current note name display needs a fixed height (e.g., `min-height: 2em` or similar) so it doesn't cause layout shift when the note name appears/disappears.

---

### 3. XY Pad (09-04) — Sound doesn't update
**Severity:** Critical — core functionality broken
**Symptom:** The numbers on the display change when dragging, but the oscillator frequency/gain does NOT actually change. Appears to use the value from the initial press only. Moving after starting doesn't change the sound.
**Component:** `docs/.vitepress/theme/components/XYPad.vue`
**Likely causes:**
- The `oscillator.update('frequency').to(freq).from('value')` call may not be working as expected
- Check if mousemove handler is actually calling update on the oscillator
- Verify the update() API works for real-time changes on a playing oscillator
- May need to check if the oscillator reference is correct in the move handler

---

### 4. Synth Drum Kit (09-04) — No Audio
**Severity:** Critical — no sound at all
**Symptom:** Clicking pads produces no audio whatsoever.
**Component:** `docs/.vitepress/theme/components/SynthDrumKit.vue`
**Likely causes:**
- Oscillator creation/play may be failing silently
- Check if `createOscillator` returns what the component expects
- The onPlayRamp scheduling may be incorrect
- Check browser console for errors
- Verify initAudio() is being called before play

---

### 5. Sampled Drum Kit (09-05) — Flash/Flicker on Init
**Severity:** Medium — functional but poor UX
**Symptom:** When the web audio context initializes on first click, the entire instrument disappears briefly in a flash, then reappears. Also has a persistent "unavailable" state styling after init.
**Component:** `docs/.vitepress/theme/components/SampledDrumKit.vue`
**Fix:**
- The pads should be visible and clickable at all times — no need for a disabled/unavailable state
- Audio context init happens on first click (which is the interaction itself), so there's no need to visually indicate that audio isn't ready yet
- Remove any conditional rendering that hides/disables the pads during init
- Keep loading state only for actual sample loading (network fetch), but show it as a subtle indicator, not by hiding the pads

---

### 6. Soundfont Piano (09-05) — Flash/Flicker on Init
**Severity:** Medium — same issue as sampled drum kit
**Symptom:** Piano disappears and flashes while the web audio context is loading.
**Component:** `docs/.vitepress/theme/components/SoundfontPiano.vue`
**Fix:** Same approach — keep the piano keyboard visible at all times. Show loading indicator as overlay or text, don't hide the keyboard. The soundfont load (1.4MB) is worth showing a progress indicator for, but the keyboard itself should remain visible.

---

### 7. Timing Basics (09-06) — Needs Inline Code Snippets
**Severity:** Low — functional but could be more educational
**Symptom:** The buttons work, but there's no code context near them. User has to scroll down to see what API is being used.
**Component:** `docs/.vitepress/theme/components/TimingDemo.vue` and/or `docs/examples/timing.md`
**Fix:** Add simplified pseudocode snippets near each button/section within the component itself. Not full imports or setup — just the key API call:
- Section 1: `sound.play()`
- Section 2: `sound.playIn(1) // plays in 1 second`
- Section 3: `s1.playAt(now); s2.playAt(now + 0.5); s3.playAt(now + 1.0)`
- Section 4: `[c, e, g].forEach(osc => osc.playAt(now)) // perfect sync`

---

### 8. Audio Routing (09-06) — Wrong Oscillator Type
**Severity:** Medium — functional but misleading
**Symptom:** The current oscillator type makes it sound like the distortion is actually cleaning up the sound, rather than adding grit. The base tone is already so harsh that distortion doesn't sound different enough.
**Component:** `docs/.vitepress/theme/components/DistortionDemo.vue`
**Fix:** Use a cleaner oscillator waveform (sine or triangle) so the distortion effect is clearly audible as a transformation. Sawtooth is already harmonically rich, so distortion on sawtooth sounds similar to clean sawtooth. A sine wave → distortion makes the effect dramatic and obvious.

---

### 9. Filter Demo (09-07) — Runtime Error
**Severity:** Critical — broken
**Symptom:** Clicking Play results in error: `source.update is not a function`
**Component:** `docs/.vitepress/theme/components/FilterDemo.vue`
**Likely cause:** The component is calling `.update()` on a source that doesn't have that method. Check:
- If source is a Sound (from createSound), it may not have update() — that's an Oscillator method
- If source is created with createOscillator, verify the returned object has update()
- If using white noise (createWhiteNoise), check if that returns an object with update()
- The filter parameter updates may need a different approach (direct AudioParam manipulation or re-creation)
