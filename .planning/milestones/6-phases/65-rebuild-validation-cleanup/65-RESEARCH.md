## Common Pitfalls

### Pitfall 1: Forgetting Build Order
**What goes wrong:** Running only `vitepress build` without TypeDoc first produces incomplete llms-full.txt
**Why it happens:** API reference pages are generated by TypeDoc before VitePress builds
**How to avoid:** Always use `pnpm build` which chains the full pipeline
**Warning signs:** Missing API reference content in llms-full.txt

### Pitfall 2: Checking Stale Dist
**What goes wrong:** Verifying old dist/ output and claiming URLs are fixed
**Why it happens:** dist/ from a previous build still contains doubled paths
**How to avoid:** Delete dist/ before rebuild, or verify timestamps
**Warning signs:** Doubled `/ez-web-audio/ez-web-audio/` in any URL

### Pitfall 3: VALIDATION.md Status Inconsistency
**What goes wrong:** Setting `nyquist_compliant: true` but leaving sign-off checkboxes unchecked
**Why it happens:** Mechanical update without reviewing each checkbox
**How to avoid:** Walk through each checkbox and verify the condition is actually met
**Warning signs:** Checked frontmatter but unchecked sign-off list

### Pitfall 4: Human Verification Scope
**What goes wrong:** Skipping human verification checks or rubber-stamping them
**Why it happens:** All automated checks already pass; human checks feel redundant
**How to avoid:** Each human check tests audio/visual behavior that cannot be automated
**Warning signs:** Verification report says "confirmed" without evidence of dev server running
