Create `src/utils/timeout.test.ts` testing `audioContextAwareTimeout` from `@utils/timeout`.

Mock `window.requestAnimationFrame` with `vi.fn()` that calls the callback synchronously (or use `vi.useFakeTimers()` where needed).
Mock `window.setTimeout` for the fallback path.

Test cases:

1. **Fallback when no audioContext** — Pass `null` (cast as any). Verify `console.warn` is called. Verify returned `setTimeout` delegates to `window.setTimeout`. Verify returned `clearTimeout` delegates to `window.clearTimeout`.

2. **setTimeout schedules a task** — Create timer functions with valid audioContext. Call `setTimeout(fn, 500)`. Verify `requestAnimationFrame` is called (scheduler starts). Verify `fn` is NOT called immediately.

3. **setTimeout returns unique IDs** — Call `setTimeout` twice, verify returned IDs are different numbers.

4. **clearTimeout cancels a pending task** — Schedule a task, then `clearTimeout(id)`. Advance time past the delay. Verify the callback was NOT invoked.

5. **Callback fires when audioContext.currentTime advances past due time** — Create audioContext mock. Call `setTimeout(fn, 500)`. Manually set `audioContext.currentTime` to 0.6 (600ms). Trigger the RAF callback manually. Verify `fn` was called.

6. **Multiple tasks fire in order** — Schedule two tasks at different delays. Advance audioContext.currentTime past both. Trigger RAF. Verify both callbacks fired.

7. **Scheduler stops when no tasks remain** — Schedule one task. Advance time, trigger RAF so task fires and is removed. Verify RAF is NOT called again (no more scheduling).

8. **Scheduler continues while tasks remain** — Schedule two tasks at different times. Advance time past only the first. Trigger RAF. Verify only first fired. Verify RAF was called again for the second.

For mocking RAF, use `vi.stubGlobal('requestAnimationFrame', vi.fn((cb) => { rafCallback = cb; return 1 }))` pattern so you can manually invoke the scheduler.
