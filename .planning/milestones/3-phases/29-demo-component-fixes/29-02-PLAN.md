**PianoKeyboard.vue** (M-14): Currently `handleTouchStart` emits `noteOn` and `handleTouchEnd` emits `noteOff`, but there is NO `touchmove` handler that detects when a finger slides from one key to another. On mobile, dragging from C4 to D4 results in C4 stuck playing and D4 never triggered.

Fix: Add a `handleTouchMove` function and wire it to `@touchmove.prevent` on each key element.

1. Add a `currentTouchNote` ref to track which note the touch is currently over:
```typescript
const currentTouchNote = ref<string | null>(null)
```

2. Update `handleTouchStart` to set `currentTouchNote`:
```typescript
function handleTouchStart(event: TouchEvent, note: string) {
  currentTouchNote.value = note
  emit('noteOn', note)
}
```

3. Add `handleTouchMove` that uses `document.elementFromPoint` to detect key changes:
```typescript
function handleTouchMove(event: TouchEvent) {
  if (event.touches.length === 0) return

  const touch = event.touches[0]
  const element = document.elementFromPoint(touch.clientX, touch.clientY) as HTMLElement | null
  if (!element) return

  // Walk up to find a .key element with aria-label containing the note
  const keyEl = element.closest('.key') as HTMLElement | null
  if (!keyEl) return

  // Extract note from aria-label "Play C4" -> "C4"
  const ariaLabel = keyEl.getAttribute('aria-label') || ''
  const noteMatch = ariaLabel.match(/Play (.+)/)
  if (!noteMatch) return

  const newNote = noteMatch[1]
  if (newNote !== currentTouchNote.value) {
    // Finger moved to a different key
    if (currentTouchNote.value) {
      emit('noteOff', currentTouchNote.value)
    }
    currentTouchNote.value = newNote
    emit('noteOn', newNote)
  }
}
```

4. Update `handleTouchEnd` to use `currentTouchNote`:
```typescript
function handleTouchEnd() {
  if (currentTouchNote.value) {
    emit('noteOff', currentTouchNote.value)
    currentTouchNote.value = null
  }
}
```

5. In the template, update the key div's event handlers:
- Change `@touchstart.prevent="handleTouchStart($event, key.note)"` (keep as-is)
- Change `@touchend.prevent="handleTouchEnd(key.note)"` to `@touchend.prevent="handleTouchEnd"` (no arg needed)
- Add `@touchmove.prevent="handleTouchMove"` to each key element

Note: The `handleTouchEnd` function signature changes — it no longer takes a note parameter since `currentTouchNote` tracks the active note.

Fix: Update the cleanup to stop any active notes. The `Font` class doesn't have a global stop, but we can track active notes and stop them. However, SampledNote (which Font.play returns) are one-shot sounds with short durations that naturally decay. The more practical fix is to null the `font` reference AND clear `activeNotes` so the UI stays consistent, and also call `font.getNotes()` to get all SampledNote instances and stop any that are playing.

Actually, looking at the code more carefully: `font.play(note)` fires and forgets. There's no reference stored to stop individual notes. The Font class stores SampledNote instances internally. The simplest correct fix is:

1. Store references to playing notes so we can stop them
2. Or, since SampledNote extends Sound which has `.stop()`, we can store the returned value from `font.play()` — BUT `Font.play()` returns void.

The practical fix: `Font` has a `getNotes()` accessor that returns the array of `SampledNote` instances. Each SampledNote has an `isPlaying` property and a `stop()` method. Update cleanup:

onUnmounted(() => {

      // Stop any currently playing notes

      for (const note of notes) {

          try { note.stop() } catch {}
        }
      }
      font = null
    }
  }
  catch (e) {

  }
