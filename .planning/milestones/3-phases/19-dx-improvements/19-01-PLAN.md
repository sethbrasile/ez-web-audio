  <files>src/base-sound.ts, src/base-sound.test.ts</files>
  <action>
  **DX-01: Auto-rewire on bypass toggle**

  The Effect interface has a `bypass` property. Currently, after toggling `effect.bypass`, the user must call `sound.rewireEffects()` manually. The goal is true bypass via physical disconnect-and-rewire, happening automatically.

  Strategy: In `addEffect()`, wrap the effect's bypass setter with a Proxy or override that calls `this.wireEffectChain()` when bypass changes. This keeps the Effect interface unchanged while adding the auto-rewire behavior.

  Implementation approach:
  1. In `addEffect()`, after pushing the effect, intercept the bypass property on the effect object. Use `Object.defineProperty` to wrap the existing bypass getter/setter:
     - Save reference to the effect's existing bypass descriptor (via `Object.getOwnPropertyDescriptor` on the prototype or the object itself)
     - Define a new property on the effect instance that delegates to the original get/set but also calls `this.wireEffectChain()` after the setter runs
     - Store the original descriptor so `removeEffect()` can restore it
  2. In `removeEffect()`, restore the original bypass behavior (remove the override)
  3. The `wireEffectChain()` method already skips bypassed effects (line ~242: `if (!effect.bypass)`), so auto-rewire will work correctly
  4. Keep `rewireEffects()` public for backwards compatibility but it becomes optional

  **DX-03: addEffects batch method**

  Add `addEffects(effects: Effect[], position?: number): this` to BaseSound:
  - Accepts an array of effects
  - If position given, inserts all at that position (in order)
  - If no position, appends all
  - Calls `wireEffectChain()` only ONCE after all effects are added (not per-effect)
  - Apply the bypass interception to each added effect
  - Debug log once showing all added effects

  Tests to add:
  - Test that toggling `effect.bypass` on an effect attached to a sound calls wireEffectChain automatically (spy on wireEffectChain or verify chain state)
  - Test that addEffects adds multiple effects and wires chain once
  - Test that removeEffect restores original bypass behavior
  - Test that bypass auto-rewire works mid-playback (no errors thrown)
  </action>

  Run `pnpm typecheck` — no type errors.
  </verify>

  - `addEffects([e1, e2])` adds both effects in one call
  - removeEffect restores original bypass behavior on the removed effect
  - All existing base-sound tests still pass

  3. In `src/effects/effect-wrapper.ts`: Same for `wrapEffect(externalEffect)`.

Extract it to a new small module `src/audio-context.ts` that both `src/index.ts` and the effect factories can import from. Move `_audioContext`, `getOrCreateAudioContext`, `unlockAudioContext`, and `iosWorkaroundPerformed` there. Update `src/index.ts` to import from `src/audio-context.ts`.
