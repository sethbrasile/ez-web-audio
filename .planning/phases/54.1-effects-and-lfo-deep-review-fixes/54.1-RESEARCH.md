# Phase 54.1: Effects and LFO Deep Review Fixes — Research

**Researched:** 2026-02-28
**Domain:** Web Audio API — LFO lifecycle, BaseEffect completeness, input validation, performance, test coverage
**Confidence:** HIGH — all findings verified directly against source code

## Summary

Phase 54.1 consolidates ALL findings from the 2026-02-28 deep review of Phases 53 (Built-in Effects) and 54 (LFO). The work splits into 5 independent groups: LFO lifecycle bugs, BaseEffect completeness, input validation, performance polish, and test coverage. All 5 groups were approved by the user.

The most critical issue (C1) is that `_patchDispose()` monkey-patches target dispose methods directly on instances. If two LFOs connect to the same target, the second LFO's patch overwrites the first's reference chain — meaning the first LFO's cleanup is permanently lost. The fix replaces this with an event listener on a `'dispose'` event dispatched by BaseSound's `dispose()` method. However, BaseSound currently does NOT dispatch a `'dispose'` event before silencing itself — it just overwrites `dispatchEvent`. This is the most architecturally significant change: either BaseSound needs to emit a `'dispose'` event before silencing, or LFO needs a different cleanup hook.

The other four groups are smaller and straightforward: JSDoc alignment, missing accessor/export/dispose on BaseEffect, validation guards across all setters, and micro-optimizations to distortion curve allocation and reverb parameter transitions.

**Primary recommendation:** Tackle groups in dependency order — Group 1 (C1/H1/H2/M1) first since Group 2's M4 (dispose on BaseEffect) follows naturally, then Groups 3 and 4 in parallel since they're independent, then Group 5 last (it tests the fixes).

## Architecture Patterns

### Current LFO dispose() approach (the bug)

```typescript
// src/lfo.ts:605-625 — _patchDispose() — THE BROKEN PATTERN
private _patchDispose(target: LFOTarget): void {
  if (this._disposePatchMap.has(target)) return  // only patches once per LFO

  const targetWithDispose = target as { dispose?: () => void }
  if (typeof targetWithDispose.dispose !== 'function') return

  const origDispose = targetWithDispose.dispose.bind(target)
  targetWithDispose.dispose = () => {      // OVERWRITES the instance method
    this._cleanupTarget(target)
    origDispose()
  }
  this._disposePatchMap.set(target, origDispose)
}
```

**Why it breaks with two LFOs:**
1. LFO-A patches: `target.dispose = () => { cleanupA(); origA() }`
2. LFO-B patches: `target.dispose = () => { cleanupB(); origA() }` — origA now wraps A's cleanup, not the true original!

Wait — re-reading: LFO-B's `_disposePatchMap.has(target)` returns false (it's B's own Map), so B patches too.
B sees A's patched dispose as "origDispose" and stores it. So the chain is actually:
- `target.dispose` = B's wrapper → calls `cleanupB()` + `origDispose_from_B` (which is A's wrapper → `cleanupA()` + `origA`)

This chain actually WORKS... until A's dispose() is also called, which restores `origA` onto the target, severing B's chain. The real break is in `LFO.dispose()`:

```typescript
// src/lfo.ts:349-352 — restores patched methods on LFO dispose
for (const [target, origDispose] of this._disposePatchMap) {
  (target as unknown as { dispose: () => void }).dispose = origDispose
}
```

If LFO-A disposes before the target, it restores `origDispose_A` (the true original), severing LFO-B's chain.

**The correct fix:** Replace `_patchDispose` entirely with an event listener that fires when the target calls dispose. BaseSound's `dispose()` currently does NOT fire a `'dispose'` event — it just silences `dispatchEvent`. For the event pattern to work, BaseSound must emit a dispose event BEFORE silencing itself.

### Event-based cleanup pattern (the fix)

```typescript
// Option A: BaseSound emits 'dispose' event before silencing
public dispose(): void {
  if (this._disposed) return
  // ... cleanup ...
  this.dispatchEvent(new CustomEvent('dispose'))  // <-- fire before silencing
  this.dispatchEvent = () => false                // silence AFTER
  this._disposed = true
}

// LFO listens instead of patching
private _listenForDispose(target: LFOTarget): void {
  if (this._disposeListeners.has(target)) return  // already listening
  const handler = () => this._cleanupTarget(target)
  target.addEventListener('dispose', handler as EventListener)
  this._disposeListeners.set(target, handler as EventListener)
}
```

**Critical constraint:** BaseEffect does NOT extend EventTarget/TypedEventEmitter. `_patchDispose` currently skips effects that lack `dispose()`. After M4 adds `dispose()` to BaseEffect, the event pattern won't work for effects unless BaseEffect also becomes an event emitter OR we keep patching for effects and only use events for BaseSound targets.

**Resolution approach:** Use separate strategies by target type:
- `BaseSound` targets: event listener on `'dispose'` event
- `BaseEffect` targets: after M4 adds `dispose()`, keep a WeakRef or use a simple callback registration on BaseEffect

### H4/L2: Input validation for LFO syncToBPM, frequency, depth

```typescript
// src/lfo.ts:364-374 — syncToBPM validation needed

  const numerator = Number.parseInt(parts[0], 10)
  const denominator = Number.parseInt(parts[1], 10)
  // 'bad' -> NaN denominator -> NaN hz -> silent broken state
  // '1/0' -> Infinity hz

  return this
}
```

**Fix pattern:**
```typescript
syncToBPM(bpm: number, noteLength: string): this {
  if (!Number.isFinite(bpm) || bpm <= 0) {
    throw new Error(`syncToBPM: bpm must be a positive finite number, got ${bpm}`)
  }
  const parts = noteLength.split('/')
  if (parts.length !== 2) {
    throw new Error(`syncToBPM: noteLength must be in format "N/D" (e.g., "1/4"), got "${noteLength}"`)
  }
  const numerator = Number.parseInt(parts[0], 10)
  const denominator = Number.parseInt(parts[1], 10)
  if (!Number.isFinite(numerator) || !Number.isFinite(denominator) || denominator === 0) {
    throw new Error(`syncToBPM: noteLength "${noteLength}" produces invalid numerator/denominator`)
  }
  const hz = (bpm / 60) * (denominator / 4) * numerator
  if (!Number.isFinite(hz) || hz <= 0) {
    throw new Error(`syncToBPM: computed frequency ${hz} is not valid`)
  }
  this.frequency = hz
  return this
}
```

Frequency and depth setters need NaN guards:
```typescript

    throw new Error(`LFO frequency must be a positive finite number, got ${value}`)
  }
  // ... rest of setter
}

    throw new Error(`LFO depth must be a finite number, got ${value}`)
  }
  // ... rest of setter
}
```

### M8: CompressorEffect parameter validation

Web Audio spec DynamicsCompressorNode constraints:
- `threshold`: -100 to 0 dB (spec range)
- `ratio`: 1 to 20 (spec range; < 1 is undefined behavior)
- `knee`: 0 to 40 dB
- `attack`: 0 to 1 second
- `release`: 0 to 1 second

The current setters pass values directly to the AudioParam with no clamping. AudioParam has its own `minValue`/`maxValue` but some browsers don't enforce and just clamp silently. Explicit clamping gives predictable behavior and better error messages.

**Fix:** Add clamping in setters (or throw — clamping is friendlier for this API):
```typescript
set ratio(v: number) {
  this.compressorNode.ratio.value = Math.max(1, Math.min(20, v))
}
set attack(v: number) {
  this.compressorNode.attack.value = Math.max(0, Math.min(1, v))
}
set release(v: number) {
  this.compressorNode.release.value = Math.max(0, Math.min(1, v))
}
```

## Common Pitfalls

### Pitfall 1: Event listener pattern for BaseEffect targets won't work
**What goes wrong:** The event-based dispose cleanup (replacing monkey-patching) only works for `BaseSound` targets, which extend `TypedEventEmitter`. `BaseEffect` does not extend `EventTarget`.
**Why it happens:** BaseEffect is a plain class, not an event emitter.
**How to avoid:** Use event listeners for BaseSound targets; keep a simple callback map for BaseEffect targets (or make BaseEffect extend EventTarget in M4).
**Warning signs:** `target.addEventListener` is not a function on BaseEffect.

### Pitfall 2: Dispatching dispose event AFTER silencing dispatchEvent
**What goes wrong:** `BaseSound.dispose()` overwrites `dispatchEvent = () => false` to silence future events, then the 'dispose' event never fires.
**Why it happens:** The silencing happens BEFORE the dispose event would be emitted.
**How to avoid:** Emit `'dispose'` event BEFORE the `this.dispatchEvent = () => false` line.

### Pitfall 3: setTargetAtTime with timeConstant=0
**What goes wrong:** `setTargetAtTime(value, time, 0)` throws `RangeError: timeConstant must be positive` in Chrome.
**Why it happens:** The Web Audio spec requires `timeConstant > 0`.
**How to avoid:** Branch to `setValueAtTime` when duration is 0 or negative.

### Pitfall 4: WaveShaper curve reuse — wrong buffer length
**What goes wrong:** If the reused Float32Array buffer is the wrong length, WaveShaper silently uses whatever length it was given — but `waveShaperNode.curve = buffer` copies the reference, so mutations after assignment affect the applied curve.
**How to avoid:** Assign to `waveShaperNode.curve` AFTER filling the buffer. The spec says the node copies the data, so mutation after assignment is safe, but always complete the fill before assigning.

### Pitfall 5: M1 — WeakMap for _disposePatchMap won't fully work
**What goes wrong:** The review flags `_disposePatchMap` as a strong reference Map. Switching to WeakMap would allow GC, but WeakMap keys must be objects (targets are objects, so this is valid). However, WeakMap is not iterable — the current `dispose()` method iterates `_disposePatchMap` to restore originals. With WeakMap, restore-on-LFO-dispose is impossible.
**How to avoid:** If replacing monkey-patching with event listeners (C1 fix), `_disposePatchMap` is eliminated entirely — M1 resolves automatically as a side effect.
