**DrumMachine.vue** - The component calls methods that don't exist on BeatTrack:

1. Replace all `kickTrack.stopAll()`, `snareTrack.stopAll()`, `hihatTrack.stopAll()` with `.stop()` (BeatTrack has `stop()`, not `stopAll()`)
2. Replace `kickTrack.playActiveBeats(bpm.value, 1/4)` (and snare/hihat) with `kickTrack.playBeats(bpm.value, 1/4)` - the `playActiveBeats` method exists but works identically to `playBeats` for our use case since beats already have active states set. Actually both methods exist on BeatTrack, but they both use the scheduler. The issue is likely that `playActiveBeats` triggers `callPlayMethodOnBeats` with 'ifActivePlayIn' which is the OLD non-scheduler approach. Use `playBeats()` instead which uses the lookahead scheduler.
3. Replace `kickTrack.changeGainTo(...)` with direct gain manipulation. BeatTrack extends Sampler which does NOT have `changeGainTo` (that's on BaseSound). Instead, iterate over the sampler's sounds if needed, or remove volume control for now. Actually, check if Sampler has changeGainTo - it doesn't inherit from BaseSound. Remove the changeGainTo calls and the volume watchers. The volume sliders can set gain on individual beats' play calls instead. Simplest fix: remove the changeGainTo calls (lines 145-147) and the volume watchers (lines 205-213) since BeatTrack/Sampler don't support them. Keep the volume UI but make it non-functional for now, or remove it entirely.
4. The `on('beat', ...)` event listener pattern is correct per the BeatTrack API.
5. In the `onUnmounted`, change `stopAll()` to `stop()`.

**XYPad.vue** - Frequency/gain don't update while dragging:

1. Line 191: `oscillator.update('frequency').to(frequency).from('value')` - the `from()` method only accepts 'ratio', 'inverseRatio', or 'percent'. `'value'` is not a valid option and will throw. Change to `oscillator.update('frequency').to(frequency).from('ratio')`. For frequency, 'ratio' passes the value through directly (value * 1), which is what we want since we're already computing the exact Hz value.
2. Line 192: `oscillator.update('gain').to(currentGain.value).from('ratio')` - this is already correct. Keep as-is.
3. The core issue may also be that Oscillator creates a NEW OscillatorNode on each `play()` call (see `setup()` method). After the initial `play()`, the `update('frequency')` call goes through the controller which sets `oscillator.frequency.value` on the OscillatorNode. This SHOULD work because the controller holds a reference to the current OscillatorNode via `updateAudioSource()`. Verify this path works.

**SynthDrumKit.vue** - No audio from any pad:

1. The `onPlayRamp` API schedules parameter changes for the NEXT `play()` call. The code creates a new oscillator each click, sets onPlayRamp, then calls play(). The issue is that `onPlayRamp` with default ramp type is 'exponential', and exponential ramps CANNOT reach 0 (mathematical limitation). Line 94: `osc.onPlayRamp('gain').from(1).to(0).in(0.1)` - ramping gain to exactly 0 with exponential will throw or produce silence. Fix: use a small value like 0.001 instead of 0, OR pass 'linear' as the ramp type. Same issue on lines 117, 141, 196, 229.
2. Also line 92: `osc.onPlayRamp('frequency').from(150).to(0.01).in(0.1)` - frequency to 0.01 with exponential should work (> 0), but is extremely low. This should be fine.
3. Line 95: `osc.changeGainTo(0.8)` is called AFTER `onPlayRamp('gain').from(1).to(0)`. The `changeGainTo` immediately sets gain to 0.8, but then `play()` triggers `setup()` which applies the onPlayRamp starting value of 1. So `changeGainTo` before `play()` is overridden. This is fine - the ramp from 1 to 0 is what matters. But the gain being set to 0.8 has no effect. Remove the `changeGainTo` calls or move them.
4. Fix ALL `onPlayRamp('gain').from(X).to(0)` to use `.to(0.001)` to avoid the exponential-ramp-to-zero issue. Alternatively, since `onPlayRamp` accepts an optional ramp type as second arg: `osc.onPlayRamp('gain', 'linear').from(1).to(0).in(0.1)`.
5. For the hi-hat (lines 196): same fix for `osc.onPlayRamp('gain').from(0.3).to(0).in(0.08)`.
6. For createWhiteNoise snare crack (line 141): `noise.onPlayRamp('gain').from(1).to(0).in(0.15)` - same exponential-to-zero issue. Fix with linear or to(0.001).
