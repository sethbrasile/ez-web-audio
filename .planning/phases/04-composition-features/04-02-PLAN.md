<feature>
  <name>BeatTrack timing control and events</name>
  <files>src/beat-track.ts, src/beat-track.test.ts, src/events/event-types.ts</files>
  <behavior>
    BeatTrack needs stop/pause/resume, tempo change, and beat event emission.

    **Current state:**
    - BeatTrack extends Sampler
    - playBeats/playActiveBeats schedule all beats at once via callPlayMethodOnBeats
    - No way to stop, pause, or change tempo mid-playback

    **New architecture (lookahead scheduler):**
    - Replace one-shot scheduling with lookahead scheduler pattern
    - Schedule beats 100ms ahead with 25ms check interval
    - Allows stop/pause/tempo change to take effect on next beat

    **Stop (CONTEXT.md: "cuts immediately"):**
    - `stop()` clears scheduler timer, resets beat index to 0
    - Emits 'stop' event

    **Pause (CONTEXT.md: "preserves beat position"):**
    - `pause()` clears scheduler timer, stores current beat index
    - Emits 'pause' event with beatIndex

    **Resume:**
    - `resume()` restarts scheduler from paused beat index
    - Emits 'resume' event with beatIndex

    **Tempo change (CONTEXT.md: "takes effect on next beat"):**
    - `setTempo(bpm)` updates tempo value
    - Next beat interval calculation uses new tempo
    - No rescheduling of already-scheduled beats

    **Beat events (for UI sync):**
    - Emit 'beat' event in scheduleBeat() at SCHEDULE time (lookahead), NOT at play time
    - This is critical: emit when beat is scheduled to audio system, not when audio actually plays
    - Event includes: time (scheduled time), beatIndex, active (is beat active or rest), source
    - UI can use scheduled time for precise animation sync (gets ~100ms advance notice)

    **Event types (add to event-types.ts):**
    - BeatEventDetail: { time, beatIndex, active, source }
    - BeatTrackEventMap: { beat, pause, resume, stop }

    **Test cases:**
    - playActiveBeats starts lookahead scheduler
    - stop() stops scheduler, resets to beat 0
    - pause() stops scheduler, preserves beat index
    - resume() continues from paused beat index
    - setTempo() changes tempo (new tempo applies to future beats)
    - 'beat' event emitted for each scheduled beat
    - 'beat' event includes correct beatIndex and active flag
    - 'pause' event includes beatIndex
    - 'resume' event includes beatIndex
    - 'stop' event emitted
    - Multiple pause/resume cycles work correctly
  </behavior>
