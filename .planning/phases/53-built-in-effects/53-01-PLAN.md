# Plan 53-01: BaseEffect + Delay Effect

## Objective

Create the shared `BaseEffect` abstract class that provides wet/dry mixing, bypass, and `rampTo()` for all effects. Then build the first new effect — `DelayEffect` — on top of it. Also refactor `FilterEffect` to extend `BaseEffect` to validate the design.

## Context

@src/effects/filter-effect.ts (pattern to follow, then refactor)
@src/effects/index.ts (exports to update)
@src/effects/effect-wrapper.ts (reference: wet/dry routing pattern)
@src/utils/equal-power-crossfade.ts (shared crossfade utility)
@src/audio-context.ts (getOrCreateAudioContext for factory functions)
@CLAUDE.md (project conventions)

## must_haves

- BaseEffect abstract class with wet/dry mixing, bypass, and rampTo()
- FilterEffect refactored to extend BaseEffect (existing tests still pass)
- DelayEffect with configurable time, feedback, and mix
- createDelay() factory function with context-free pattern
- All existing effect tests still pass after refactor

## Tasks

<task type="auto" tdd="true">
  <name>Task 1: Create BaseEffect abstract class</name>
  <files>src/effects/base-effect.ts, src/effects/base-effect.test.ts</files>
  <behavior>
    - BaseEffect cannot be instantiated directly (abstract)
    - Subclass with minimal implementation can be created
    - input/output return valid AudioNodes
    - bypass defaults to false; setting true routes signal dry
    - mix defaults to 1; setting to 0.5 applies equal-power crossfade
    - mix is clamped to 0-1
    - rampTo('mix', 0.5, 1) schedules setTargetAtTime on wetGain
    - rampTo() with unknown param name is a no-op (no throw)
  </behavior>
  <action>
    Create `src/effects/base-effect.ts` with:

    1. Abstract class `BaseEffect` implementing `Effect` interface
    2. Constructor takes `AudioContext`, creates inputNode, outputNode, dryGain, wetGain (all GainNodes)
    3. Wire dry path: inputNode -> dryGain -> outputNode
    4. Wire wet merge: wetGain -> outputNode
    5. Subclasses must wire: inputNode -> [their effect nodes] -> wetGain
    6. Protected `audioContext` property for subclass access
    7. Getters/setters for `bypass` (boolean) and `mix` (number, clamped 0-1)
    8. `applyMix()` private method using `applyEqualPowerCrossfade(dryGain, wetGain, mix, bypass)`
    9. `rampTo(param: string, value: number, duration: number)` public method:
       - For 'mix': use `setTargetAtTime` on wetGain/dryGain with time constant = duration/3
       - Delegates to `getAudioParam(name)` abstract method for effect-specific params
       - If param not found, no-op (don't throw)
    10. Abstract method `getAudioParam(name: string): AudioParam | null` for subclass param mapping

    Export `BaseEffect` from the file.

    For tests, create a concrete test subclass `TestEffect` that extends BaseEffect with a simple GainNode as the effect chain. Test all BaseEffect behaviors.
  </action>
  <verify>
    <automated>pnpm test src/effects/base-effect.test.ts</automated>
  </verify>
  <done>BaseEffect abstract class exists with wet/dry, bypass, rampTo. All tests pass.</done>
</task>

  <behavior>
    - All existing FilterEffect tests still pass unchanged
    - FilterEffect no longer has its own inputNode/outputNode/dryGain/wetGain fields
    - FilterEffect.rampTo('frequency', 1000, 2) schedules param ramp
    - FilterEffect.rampTo('q', 5, 1) schedules param ramp
    - FilterEffect.rampTo('gain', 3, 0.5) schedules param ramp
  </behavior>
  <action>
    Refactor `FilterEffect` to extend `BaseEffect`:

    1. Remove duplicated fields: inputNode, outputNode, dryGain, wetGain, _bypass, _mix
    2. Remove duplicated methods: input/output getters, bypass/mix getters/setters, applyMix()
    3. Call `super(audioContext)` in constructor
    4. Wire effect chain: `this.inputNode.connect(this.filterNode)` and `this.filterNode.connect(this.wetGain)` (inputNode and wetGain are now from BaseEffect)
    5. Implement `getAudioParam(name)`: map 'frequency' -> filterNode.frequency, 'q' -> filterNode.Q, 'gain' -> filterNode.gain, 'detune' -> filterNode.detune
    6. Keep all existing getters/setters for frequency, q, gain, detune, type

    Run existing FilterEffect tests — they should all pass without changes. Add rampTo tests.

    Note: Do NOT refactor GainEffect. It's a single-node effect with different mix semantics and doesn't fit the BaseEffect pattern.
  </action>
  <verify>
    <automated>pnpm test src/effects/filter-effect.test.ts</automated>
  </verify>
  <done>FilterEffect extends BaseEffect, all existing tests pass, rampTo works for filter params.</done>

<task type="auto" tdd="true">
  <name>Task 3: Create DelayEffect with factory function</name>
  <files>src/effects/delay-effect.ts, src/effects/delay-effect.test.ts, src/effects/index.ts, src/index.ts</files>
  <behavior>
    - createDelay() with no args creates delay with defaults (time: 0.3, feedback: 0.4)
    - createDelay({ time: 0.5, feedback: 0.7, mix: 0.6 }) respects all options
    - delay.time getter returns current delay time
    - delay.time setter updates delay time in real-time
    - delay.feedback getter/setter controls feedback amount
    - delay.feedback is clamped to 0-0.99 (prevents blowup)
    - delay.maxTime defaults to 2.0 (set at construction, read-only after)
    - delay.bypass routes signal dry
    - delay.mix controls wet/dry
    - delay.rampTo('time', 0.1, 2) schedules smooth ramp
    - delay.rampTo('feedback', 0.8, 1) schedules smooth ramp
    - createDelay(audioContext, opts) overload works (context-free pattern)
    - Delay implements Effect interface (input/output AudioNodes)
  </behavior>
  <action>
    Create `src/effects/delay-effect.ts`:

    1. `DelayOptions` interface: `time?: number` (default 0.3), `feedback?: number` (default 0.4), `mix?: number` (default 1), `maxTime?: number` (default 2.0)
    2. `DelayEffect` class extending `BaseEffect`
    3. Constructor creates:
       - `DelayNode` with maxDelayTime from options
       - `GainNode` for feedback
    4. Signal routing:
       - `this.inputNode.connect(delayNode)`
       - `delayNode.connect(feedbackGain)` (feedback path)
       - `feedbackGain.connect(delayNode)` (loop)
       - `delayNode.connect(this.wetGain)` (to output via BaseEffect)
    5. Getters/setters for `time` and `feedback`
       - `feedback` setter clamps to [0, 0.99]
    6. `getAudioParam()` maps 'time' -> delayNode.delayTime, 'feedback' -> feedbackGain.gain
    7. `createDelay()` factory with context-free overloads (same pattern as createFilterEffect)

    Export from `src/effects/index.ts` and `src/index.ts`.
  </action>
  <verify>
    <automated>pnpm test src/effects/delay-effect.test.ts</automated>
  </verify>
  <done>createDelay() works with addEffect(), all params controllable, feedback clamped to prevent blowup.</done>
</task>
