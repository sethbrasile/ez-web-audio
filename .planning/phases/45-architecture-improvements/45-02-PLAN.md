In `src/base-sound.ts`, refactor the `stopAt(time)` method (around line 977):

Current behavior: When `time !== currentTime`, it schedules a JavaScript timeout via `_trackedTimeout` to call `stop()` at the right moment AND passes `time` to `node.stop(time)` inside that timeout. This is double-scheduling: the JS timeout fires approximately when it should, then calls `node.stop(time)` with the original time (which may already be in the past by then).

New behavior:
1. For `time === currentTime` (immediate stop): Keep the existing synchronous stop logic as-is.
2. For `time > currentTime` (future stop):
   - Call `node.stop(time)` immediately — the Web Audio API will handle the precise timing.
   - Schedule a `_trackedTimeout` for `(time - currentTime) * 1000` milliseconds that only handles the state cleanup: set `_isPlaying = false`, emit 'stop' event, call `_cancelPendingTimeouts()`, and run debug log.
   - This way, the audio stops precisely via the Web Audio scheduler, and the JS timeout handles state bookkeeping approximately when the audio stops.

The key insight: `node.stop(time)` is sample-accurate in the Web Audio API. The JS timeout is only needed for updating `_isPlaying` and emitting events — it doesn't need to actually stop the node.

Refactored code structure:
```typescript
public async stopAt(time: number): Promise<void> {
  await this.audioContext.resume()

  const node = this.audioSourceNode
  const currentTime = this.audioContext.currentTime

  if (time <= currentTime) {
    // Immediate stop
    this._cancelPendingTimeouts()
    if (this._isPlaying) {
      this._isPlaying = false
      this.emit('stop', { time: this.audioContext.currentTime, source: this })
      debugEvent(this, 'stop', this.audioContext.currentTime)
      node.stop()
    }
  } else {
    // Schedule precise audio stop via Web Audio API
    node.stop(time)
    // Schedule state cleanup via JS timeout (approximate timing is fine for state/events)
    this._trackedTimeout(() => {
      this._cancelPendingTimeouts()
      if (this._isPlaying) {
        this._isPlaying = false
        this.emit('stop', { time: this.audioContext.currentTime, source: this })
        debugEvent(this, 'stop', this.audioContext.currentTime)
      }
    }, (time - currentTime) * 1000)
  }
}
```

Important: The `node.stop(time)` call is moved OUTSIDE the timeout so the Web Audio scheduler handles the precise audio cutoff. The timeout only handles JavaScript state.
