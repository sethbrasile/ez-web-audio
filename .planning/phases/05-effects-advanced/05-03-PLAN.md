Create the Analyzer class wrapping Web Audio AnalyserNode:

1. **src/analyzer.ts:**

```typescript
export interface AnalyzerOptions {
  fftSize?: number           // Default 2048, power of 2 (32-32768)
  minDecibels?: number       // Default -100
  maxDecibels?: number       // Default -30
  smoothingTimeConstant?: number  // Default 0.8 (0-1)
}
```

**Analyzer class:**
- Constructor takes AudioContext and optional AnalyzerOptions
- Creates internal AnalyserNode with configured options
- Pre-allocates typed arrays for data (frequencyData, timeDomainData, floatFrequencyData)
- Array sizes based on frequencyBinCount (half of fftSize)

**Properties:**
- `input: AnalyserNode` - The node to connect to (for routing)
- `frequencyBinCount: number` - Read-only, number of data points
- `fftSize: number` - Getter/setter for FFT size (validates power of 2)
- `minDecibels: number` - Getter/setter
- `maxDecibels: number` - Getter/setter
- `smoothingTimeConstant: number` - Getter/setter

**Polling methods (call in requestAnimationFrame):**
- `getFrequencyData(): Uint8Array` - Returns byte frequency data (0-255 values)
- `getTimeDomainData(): Uint8Array` - Returns waveform data (128 = zero crossing)
- `getFloatFrequencyData(): Float32Array` - Returns precise dB values

Each method:
1. Calls the corresponding AnalyserNode method to fill the pre-allocated array
2. Returns the pre-allocated array (same reference, user should use immediately or copy)

2. **Factory function:**
```typescript
export function createAnalyzer(audioContext: AudioContext, options?: AnalyzerOptions): Analyzer
```

- getFloatFrequencyData returns Float32Array of correct size
- fftSize must be power of 2 (validation)
- frequencyBinCount = fftSize / 2
- input property is AnalyserNode

```typescript
public setAnalyzer(analyzer: Analyzer | null): this {
  this._analyzer = analyzer
  this.wireEffectChain()  // Re-wire to include analyzer
  return this
}

public getAnalyzer(): Analyzer | null {
  return this._analyzer
}
```

Modify wireEffectChain() to include analyzer at end of chain:
- Chain order: effectChainInput -> [effects] -> gainNode -> pannerNode -> analyzer?.input -> _destination
- If analyzer is set, pannerNode connects to analyzer.input, and analyzer.input connects to _destination
- If analyzer is null, pannerNode connects directly to _destination
- Note: AnalyserNode passes through audio, so it can be inserted without breaking the chain

Per RESEARCH.md open question: Attach analyzer AFTER effects (shows processed signal). This is the correct choice for most visualization use cases.
