<task type="auto">
  <name>Task 1: Add effect chain infrastructure to BaseSound</name>
  <files>src/base-sound.ts</files>
  <action>
Modify BaseSound to support persistent effect chains:

1. **Add protected members:**
```typescript
protected effects: Effect[] = []
protected effectChainInput: GainNode  // Entry point for effect chain
protected _destination: AudioNode     // Configurable destination
```

2. **Initialize in constructor:**
- Create effectChainInput as a GainNode
- Set _destination to audioContext.destination by default
- Call wireEffectChain() to set up initial routing

3. **Add wireEffectChain() private method:**
- Disconnects existing chain safely (use disconnect(destination) not disconnect())
- Builds chain: effectChainInput -> [effects in order] -> gainNode -> pannerNode -> _destination
- For each effect, connect to effect.input, then continue from effect.output
- Skip effects where effect.bypass === true
- Called when effects are added/removed/reordered, NOT on every play()

4. **Add public methods:**

`addEffect(effect: Effect, position?: number): this`
- If position provided, insert at that index; otherwise append
- Call wireEffectChain() to rewire
- Return this for chaining

`removeEffect(effect: Effect): this`
- Find and remove effect from effects array
- Call wireEffectChain() to rewire
- Return this for chaining

`getEffects(): readonly Effect[]`
- Return shallow copy of effects array

`setDestination(node: AudioNode): this`
- Set _destination to provided node
- Call wireEffectChain() to rewire
- Return this for chaining

5. **Modify setup() in subclasses (Sound, Oscillator):**
- Current setup() creates source and calls wireConnections()
- Change: setup() creates source and connects to effectChainInput
- The effect chain is already wired, so only source needs reconnecting

Note: The existing `connections` array is separate from `effects`. Keep backward compatibility:
- connections = user-managed AudioNode array (existing functionality)
- effects = Effect instances with bypass/mix (new functionality)
- Both can coexist. Wire order: source -> connections -> effectChainInput -> effects -> gain -> panner -> destination

Actually, per CONTEXT.md, effects replace the current connections approach. Refactor:
- Remove the current wireConnections() implementation
- Replace with the persistent effect chain approach
- Keep the connections array for backward compatibility but document it as deprecated
- New pattern: source -> effectChainInput -> effects -> gain -> panner -> destination
  </action>
