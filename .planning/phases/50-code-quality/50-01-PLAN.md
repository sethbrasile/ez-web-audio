The gain-interception logic in `BaseSound.update()` (lines 616-637) and `Oscillator.update()` (lines 233-253) is identical for the `type === 'gain'` branch. Eliminate the duplication:

1. **In `src/oscillator.ts`**, modify the `update()` override so that for `'gain'`, it delegates to `super.update(type)` instead of duplicating the interception. The override only needs to exist to widen the type signature from `SoundControlType` to `ControlType`:

```typescript
public override update(type: ControlType): {
  to: (value: number) => {
    as: (method: RatioType) => void
  }
} {
  // 'gain' and 'pan' are handled by BaseSound.update() which intercepts gain for _targetGain sync.
  // Only 'frequency' and 'detune' need oscillator-specific routing.
  if (type === 'gain' || type === 'pan') {
    return super.update(type as SoundControlType)
  }
  return this.controller.update(type)
}
```

Note: `BaseSound.update()` accepts `SoundControlType` which includes `'gain'`, `'pan'`, `'detune'`. Since `'detune'` is already handled by `BaseSound.update()` → `this.controller.update(type)`, we can pass `'gain'`, `'pan'`, AND `'detune'` through to super. Only `'frequency'` is oscillator-specific. So the cleaner version is:

```typescript
public override update(type: ControlType): {
  to: (value: number) => {
    as: (method: RatioType) => void
  }
} {
  // 'frequency' is oscillator-specific; everything else delegates to BaseSound
  // which handles _targetGain interception for 'gain'.
  if (type === 'frequency') {
    return this.controller.update(type)
  }
  return super.update(type as SoundControlType)
}
```

```typescript
/**
 * Resolve a control type to its corresponding AudioParam.
 * Override in subclasses to add type-specific params (e.g., frequency).
 * @protected
 */
protected resolveParam(type: ControlType): AudioParam {
  switch (type) {
    case 'gain':
      return this.gainNode.gain
    case 'pan':
      return this.pannerNode.pan
    case 'detune':
      return this.audioSource.detune as unknown as AudioParam
    default:
      throw new Error(`Unsupported control type: '${type}'.`)
  }
}

protected applyValues(values: ParamValue[], currentTime: number): void {
  for (const item of values) {
    this.resolveParam(item.type).setValueAtTime(item.value, currentTime)
  }
}

protected applyRampValues(values: ValueAtTime[], currentTime: number, rampType: 'exponential' | 'linear'): void {
  for (const item of values) {
    const time = currentTime + item.time
    this.applyRampToParam(this.resolveParam(item.type), item.value, time, rampType)
  }
}
```

Note: `this.audioSource.detune` is typed as `{ value: number }` in the AudioSource interface, not as a full AudioParam. For the `setValueAtTime` call to work, we need to update the `AudioSource` interface to expose `detune` as `AudioParam`. Check whether this is safe with the mock. If not, keep the detune case inline via override. The practical approach: since both OscillatorNode.detune and AudioBufferSourceNode.detune ARE AudioParams in the real API (and in the mock), cast `audioSource.detune` to `AudioParam`. Update the `AudioSource` duck-type interface:

```typescript
interface AudioSource {
  detune: AudioParam
  frequency?: AudioParam
}
```

This is safe because both OscillatorNode and AudioBufferSourceNode have `detune: AudioParam`.
