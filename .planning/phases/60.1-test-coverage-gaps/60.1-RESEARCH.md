### Pattern: Extended Test Class
BeatTrack tests use an extended class to expose internal state:
```typescript
class BeatTrack extends RealBeatTrack {
  public getCurrentBeatIndex(): number { return (this as any).currentBeatIndex }
  // ... other test-only accessors
}
```
Use this pattern when internal state must be observed. Do NOT add public getters to production code for test purposes.

### Pattern: Mock AudioContext Creation
```typescript
import { AudioContext as Mock } from 'standardized-audio-context-mock'
function createMockContext() {
  return new Mock() as unknown as AudioContext
}
```

### Pattern: Spying on AudioParam for Value Verification
```typescript
const gainNode = sound.getGainNode()
const spy = vi.spyOn(gainNode.gain, 'setValueAtTime')
// ... trigger action ...
expect(spy).toHaveBeenCalledWith(expectedValue, expect.any(Number))
```
This is the key pattern needed for QC-1-15 (LFO depth verification).

### Anti-Patterns to Avoid
- **Testing internal implementation:** Test behavior through public API, not private fields. Exception: the extended BeatTrack pattern above, which is already established.
- **Testing mock behavior:** Don't test that the mock works. Test that the library calls the right Web Audio API methods with the right values.
- **Time-dependent assertions:** Use `vi.useFakeTimers()` and `vi.advanceTimersByTime()` instead of real time delays.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| AudioParam value checks | Raw property access | `vi.spyOn(param, 'setValueAtTime')` or check `.gain.value` | Mock AudioParam doesn't always persist value assignments; spies are reliable |
| Timer advancement | `setTimeout` with real time | `vi.useFakeTimers()` + `vi.advanceTimersByTime(ms)` | Deterministic, fast, no flaky tests |
| AudioContext creation | `new AudioContext()` | `new Mock() as unknown as AudioContext` | Test environment has no real audio |

## Common Pitfalls

### Pitfall 1: Mock AudioParam doesn't persist .value assignments
**What goes wrong:** Setting `gainNode.gain.value = 0.5` in mock context may not persist.
**How to avoid:** Use `vi.spyOn(gainNode.gain, 'value', 'get').mockReturnValue(0.5)` for reads, or spy on `setValueAtTime` for writes.
**Warning signs:** Test passes when checking spy calls but fails when reading `.value`.

### Pitfall 2: Fake timers must be set up before creating objects that use setTimeout
**What goes wrong:** GrainPlayer/Transport create timers in constructors. If `vi.useFakeTimers()` is called after construction, timers use real time.
**How to avoid:** Call `vi.useFakeTimers()` in `beforeEach` before creating instances. Already established in existing tests.

### Pitfall 3: Module-level imports in index.test.ts
**What goes wrong:** `index.test.ts` uses `vi.resetModules()` + dynamic `import('./index')` for each test to get fresh singleton state.
**How to avoid:** Follow the existing pattern in index.test.ts -- always `await import('./index')` in the test body, never use top-level static imports for the module under test.

### Pitfall 4: createGain spy must be set before LFO.connect()
**What goes wrong:** LFO creates depthGain GainNodes during `connect()`. If you spy after connect, you miss the node.
**How to avoid:** Set up `vi.spyOn(audioContext, 'createGain')` before calling `lfo.connect()`.

### LFO depth numeric verification pattern
```typescript
it('ratio mode: depth 0.3 with gain 1.0 produces depthGain 0.3', () => {
  const ctx = createMockContext()
  const sound = new Sound(ctx, createMockAudioBuffer(ctx))

  // Capture GainNodes created during connect
  const gainNodes: GainNode[] = []
  const origCreateGain = ctx.createGain.bind(ctx)
  vi.spyOn(ctx, 'createGain').mockImplementation(() => {
    const node = origCreateGain()
    gainNodes.push(node)
    return node
  })

  const lfo = new LFO({ depth: 0.3 })
  lfo.connect(sound, 'gain') // ratio mode by default for gain

  // The last created GainNode is the depthGain
  const depthGain = gainNodes[gainNodes.length - 1]
  expect(depthGain.gain.value).toBeCloseTo(0.3, 2)
})
```
