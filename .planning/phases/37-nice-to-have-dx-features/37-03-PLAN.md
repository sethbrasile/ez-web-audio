1. **Create `src/events/typed-event-emitter.ts`** with a mixin that adds typed event methods:

   The pattern to use is a **mixin function** (consistent with the existing `MusicallyAware` mixin pattern in this codebase):

   ```typescript
   /**
    * Mixin that adds typed event methods (on/off/once/emit) to any class
    * that extends EventTarget (or uses a delegated EventTarget).
    *
    * TMap should be a record mapping event name strings to CustomEvent types.
    */
   export function TypedEventEmitter<TMap extends Record<string, CustomEvent>>(Base: typeof EventTarget) {
     return class extends Base {
       // addEventListener overloads with type safety
       addEventListener<K extends keyof TMap & string>(
         type: K,
         listener: (event: TMap[K]) => void,
         options?: boolean | AddEventListenerOptions
       ): void
       addEventListener(
         type: string,
         listener: EventListenerOrEventListenerObject | null,
         options?: boolean | AddEventListenerOptions
       ): void
       addEventListener(
         type: string,
         listener: any,
         options?: boolean | AddEventListenerOptions,
       ): void {
         super.addEventListener(type, listener as EventListener, options)
       }

       // removeEventListener overloads
       removeEventListener<K extends keyof TMap & string>(
         type: K,
         listener: (event: TMap[K]) => void,
         options?: boolean | EventListenerOptions
       ): void
       removeEventListener(
         type: string,
         listener: EventListenerOrEventListenerObject | null,
         options?: boolean | EventListenerOptions
       ): void
       removeEventListener(
         type: string,
         listener: any,
         options?: boolean | EventListenerOptions,
       ): void {
         super.removeEventListener(type, listener as EventListener, options)
       }

       // emit helper
       protected emit<K extends keyof TMap & string>(
         type: K,
         detail: TMap[K]['detail'],
       ): void {
         const event = new CustomEvent(type, { detail })
         this.dispatchEvent(event)
       }

       // on (chainable)
       on<K extends keyof TMap & string>(
         type: K | K[],
         listener: (event: TMap[K]) => void,
       ): this {
         if (Array.isArray(type)) {
           type.forEach(t => this.addEventListener(t, listener as any))
         } else {
           this.addEventListener(type, listener)
         }
         return this
       }

       // once (chainable)
       once<K extends keyof TMap & string>(
         type: K,
         listener: (event: TMap[K]) => void,
       ): this {
         this.addEventListener(type, listener, { once: true })
         return this
       }

       // off (chainable)
       off<K extends keyof TMap & string>(
         type: K,
         listener: (event: TMap[K]) => void,
       ): this {
         this.removeEventListener(type, listener)
         return this
       }
     }
   }
   ```

   **Important implementation note:** The mixin returns a class extending EventTarget. The exact TypeScript generics may need adjustment to satisfy the type checker. Use the `MusicallyAware` mixin in `src/musical-identity.ts` as a reference for the constructor pattern. The mixin must work with both:
   - Classes that directly extend EventTarget (BaseSound, LayeredSound)
   - BeatTrack which uses a **delegated** EventTarget (private `eventTarget` property, not inheritance)

   For BeatTrack, the approach will be different: BeatTrack extends Sampler (not EventTarget), so it cannot use the mixin directly. Instead, BeatTrack should:
   - Keep its private `eventTarget` delegation pattern
   - But extract the `on/off/once` convenience methods to call the mixin's static helpers, OR
   - Simply keep BeatTrack's `on/off/once` as thin wrappers since BeatTrack's event system is inherently different (delegated, not inherited).

   **Pragmatic approach**: If the mixin gets too complex to support both inheritance patterns, use a simpler approach:
   - Create a `TypedEventEmitter` base class (extending EventTarget) with on/off/once/emit
   - Have `BaseSound extends TypedEventEmitter<SoundEventMap>` (replacing `extends EventTarget`)
   - Have `LayeredSound extends TypedEventEmitter<LayeredSoundEventMap>` (replacing `extends EventTarget`)
   - For BeatTrack: extract `on/off/once` into standalone helper functions that take an EventTarget, OR keep the existing pattern since BeatTrack already has minimal duplication (~15 lines).

   Choose whichever approach compiles cleanly and satisfies the DRY requirement. The key is eliminating the ~60 lines of addEventListener/removeEventListener overloads + ~30 lines of on/off/once from BOTH BaseSound AND LayeredSound.
