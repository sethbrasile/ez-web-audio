3. `it('once() fires handler only once')` — Subscribe with `once('stop', handler)`. Trigger the event twice (emit two 'stop' events). Verify handler called exactly once.
4. `it('on() supports chaining multiple events')` — `track.on('beat', handler1).on('stop', handler2)`. Verify both subscriptions work.

For triggering events: BeatTrack emits events when `stop()` is called (emits 'stop'). So the pattern is:
- Call `track.playActiveBeats()` to start, then `track.stop()` — this should emit 'stop'.

Simpler approach: Since `on()` wraps `addEventListener()`, spy on `addEventListener` and verify it was called with the correct arguments. Then for behavioral tests, use a real BeatTrack and trigger events by calling stop().
