**DEF-01 — Null-safe iterations in BaseSound.wireEffectChain():**

In `wireEffectChain()`, the two `for...of effects` loops already work fine since `effects` is typed as `Effect[]`. However, add null guards to skip null/undefined entries defensively. In both loops that iterate `effects`, add a `if (!effect) continue` check at the top of each loop body. This covers the case where an array slot is somehow null (e.g., from framework proxy quirks).

Similarly in Oscillator.wireConnections(), the `filters` loop at line 268 should get the same guard — but that file is NOT in this plan's scope since it only pushes valid filter nodes. The effect iteration is the primary concern.

**DEF-02 — Validate negative position in addEffect() and addEffects():**

In `addEffect()` (line 341), the current condition `position !== undefined && position >= 0 && position <= this.effects.length` silently falls through to push-to-end when position is negative. Change to: if `position !== undefined`, first check `if (position < 0) throw new Error('addEffect() position must be >= 0. Received: ' + position)`. Then check `position <= this.effects.length` for the splice, else push to end.

Apply the same pattern to `addEffects()` (line 408): throw on negative position.

**DEF-03 — Guard empty sounds in Sampler.getNextSound():**

In `getNextSound()` (line 136 of sampler.ts), add a guard at the top: `if (this.sounds.size === 0) throw new Error('Sampler has no sounds. Add sounds before calling play().')`. This prevents cryptic undefined errors when play/playIn/playAt are called on an empty Sampler.

**DEF-04 — Clear parameter arrays after applying values:**

In `base-param-controller.ts`, add a protected method `clearScheduledValues()` that resets all four arrays:
```typescript
protected clearScheduledValues(): void {
  this.startingValues = []
  this.valuesAtTime = []
  this.exponentialValues = []
  this.linearValues = []
}
```

In `sound-controller.ts`, at the END of `setValuesAtTimes()` (after all four `applyValues`/`applyRampValues` calls), call `this.clearScheduledValues()`.

In `oscillator-controller.ts`, at the END of `setValuesAtTimes()` (after applying envelope and all four apply calls), call `this.clearScheduledValues()`.

This ensures that parameter schedules from `onPlaySet()` and `onPlayRamp()` are applied once and then cleared, preventing accumulation across repeated `play()` calls.

**IMPORTANT:** The `onPlayRamp` fluent API internally calls `onPlaySet` which pushes to `startingValues`. If a user wants the SAME schedule on every play, they must call `onPlaySet`/`onPlayRamp` before each `play()`. This is the correct semantic — schedules are consumed on play, not persistent. Document this in a brief JSDoc comment on `clearScheduledValues`.
