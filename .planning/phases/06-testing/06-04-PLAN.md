Create comprehensive tests for AudioContext initialization functions.

**Test Structure:**

```typescript
import { AudioContext as Mock } from 'standardized-audio-context-mock'
import { afterEach, beforeEach, describe, expect, it, vi } from 'vitest'
```

**Tests to implement:**

1. **initAudio() basic behavior:**
   - Creates AudioContext when none exists
   - Does not recreate AudioContext on subsequent calls (singleton)
   - Returns resolved promise on success

2. **getAudioContext() behavior:**
   - Calls initAudio() internally
   - Returns the AudioContext instance
   - Returns same instance on repeated calls

3. **Error handling:**
   - Throws AudioContextError when state is 'interrupted' (iOS backgrounded)
   - Error message is actionable (tells user what to do)
   - Error includes the actual state

4. **iOS workaround flag:**
   - When `useIosMuteWorkaround=true` (default), calls unmuteIosAudio
   - When `useIosMuteWorkaround=false`, does NOT call unmuteIosAudio
   - iOS workaround only called once (not on repeated initAudio calls)

**Mocking Strategy:**

The module has private state (audioContext, iosWorkaroundPerformed). To test properly:
1. Mock the AudioContext constructor globally using `vi.mock()` or inject via `vi.spyOn(globalThis, 'AudioContext')`
2. Mock `unmuteIosAudio` import to verify it's called with correct flag
3. Use `vi.resetModules()` and dynamic import to reset module state between tests

**Example test pattern:**

```typescript
describe('initAudio', () => {
  let mockAudioContext: any
  let mockUnmute: ReturnType<typeof vi.fn>

  beforeEach(() => {
    vi.resetModules()
    mockAudioContext = new Mock()
    vi.stubGlobal('AudioContext', vi.fn(() => mockAudioContext))
    mockUnmute = vi.fn()
    vi.doMock('./utils/unmute', () => ({ default: mockUnmute }))
  })

  afterEach(() => {
    vi.unstubAllGlobals()
    vi.clearAllMocks()
  })

  it('creates AudioContext', async () => {
    const { initAudio } = await import('./index')
    await initAudio()
    expect(AudioContext).toHaveBeenCalledTimes(1)
  })

  it('reuses existing AudioContext on subsequent calls', async () => {
    const { initAudio } = await import('./index')
    await initAudio()
    await initAudio()
    expect(AudioContext).toHaveBeenCalledTimes(1)
  })
})
```

**Important considerations:**
- The test environment uses happy-dom which provides document.body for unlockAudioContext
- Use `vi.resetModules()` before each test to reset the module-level audioContext variable
- Mock audioContext.state to test interrupted state error path
- The unlockAudioContext function adds event listeners to document.body - this works in happy-dom

**Do NOT test:**
- unmute.js internals (browser-specific, requires manual testing)
- Real iOS Safari behavior (requires physical device)
- Full unlockAudioContext event listener chain (requires user interaction simulation)
