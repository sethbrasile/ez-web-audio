# 76-01: Groovebox Engine + State

> **For agentic workers:** Execute per `.planning/M8-PLAYBOOK.md`. **Blocked on:** human gate 2 (Phase 75 listening) passed. UI comes in 76-02; this plan is headless engine + state + share codec, testable without design assets.

**Goal:** A fully functional groovebox audio engine driven by a serializable state object: 4 drum lanes + bass lane + lead arp over 32 steps, BPM + swing, mute/solo, master delay/reverb sends — with URL-safe state encode/decode. Built on `@ez-web-audio/vue` + Phase 75 master bus.

**Architecture:** Pure state module (`state.ts`, `codec.ts` — unit-tested, no audio) + engine composable (`use-groovebox.ts`) that builds/rebuilds the audio graph from state. Engine consumes the composables package like any user would — friction here is binding feedback, file it.

## Global Constraints

- Existing repo samples only (the drum samples + soundfont already in `docs/public/`). Clap: if no clap sample exists, use a synthesized clap (noise burst through bandpass + envelope via core API) — do NOT source new assets.
- All audio through `getDemoMasterBus` (Phase 75).
- No new runtime dependencies. Lead arp = preset patterns, not per-step editing (spec).
- BPM range 60–180 default 120; swing 0–100% default 0; live changes must not require stop/start.

**Interfaces (exact — 76-02 and codec rely on these):**

```ts
export type LaneId = 'kick' | 'snare' | 'hihat' | 'clap' | 'bass' | 'lead'
export const STEPS = 32 as const

export interface GrooveboxState {
  v: 1
  bpm: number                          // clamp 60-180
  swing: number                        // clamp 0-100
  drums: Record<'kick' | 'snare' | 'hihat' | 'clap', number[]>  // 32 × (0|1)
  bass: (string | null)[]              // 32 × note name ('C2'..'C4') or null
  bassWave: 'triangle' | 'sawtooth' | 'square'
  lead: { on: boolean, patternId: string, root: string }
  mutes: Partial<Record<LaneId, boolean>>
  solos: Partial<Record<LaneId, boolean>>
  fx: { delay: { time: number, feedback: number, send: number }, reverb: { send: number } }
}

export function defaultState(): GrooveboxState
export function validateState(input: unknown): GrooveboxState   // clamps/repairs, never throws
export function laneAudible(state: GrooveboxState, lane: LaneId): boolean  // mute/solo resolution
```

- [ ] **Step 1: Failing tests:** `defaultState()` returns valid 32-step arrays; `validateState` clamps bpm 300→180, repairs wrong-length arrays to 32, rejects unknown waveforms to 'triangle', tolerates missing keys (spread over defaults); `laneAudible`: no solos → !muted; any solo → only soloed lanes audible regardless of mutes.
- [ ] **Step 2: FAIL run** (`pnpm test:docs`), **Step 3: implement**, **Step 4: PASS run**, **Step 5: commit** `feat(groovebox): state module`.
