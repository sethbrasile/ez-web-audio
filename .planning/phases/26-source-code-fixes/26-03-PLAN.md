<task type="auto">
  <name>Task 1: Differentiate playBeats vs playActiveBeats</name>
  <files>src/beat-track.ts</files>
  <action>
**H-5:** Both `playBeats()` and `playActiveBeats()` currently set the same state and call `this.scheduler()`. The scheduler always calls `beat.playInIfActive()`, so both methods behave identically.

Add a private field to track which mode is active:
```typescript
private _playAllBeats = false
```

In `playBeats()`, set `this._playAllBeats = true` before calling `this.scheduler()`.
In `playActiveBeats()`, set `this._playAllBeats = false` before calling `this.scheduler()`.

In the `scheduleBeat()` method (or wherever the scheduler calls `beat.playInIfActive()`), use the flag:
```typescript
if (this._playAllBeats) {
  beat.playIn(offset)         // plays unconditionally regardless of beat.active
} else {
  beat.playInIfActive(offset) // respects beat.active flag
}
```

Read the actual `scheduleBeat` method to find the exact location of the `playInIfActive` call and apply the conditional there.

**H-6:** In `resume()`, replace the restoration of `pausedBeatTime` with the current audioContext time:
```typescript
this.nextBeatTime = this.audioContext.currentTime  // NOT this.pausedBeatTime
```

This prevents the scheduler while loop from catching up hundreds of beats after a pause. Also preserve the `_playAllBeats` flag across pause/resume (do not reset it in pause or resume — it should persist until the next playBeats/playActiveBeats call).
  </action>
  <verify>`pnpm test` passes. Read scheduleBeat — conditional on _playAllBeats. Read resume — nextBeatTime set to audioContext.currentTime.</verify>
  <done>playBeats() plays all beats unconditionally. playActiveBeats() only plays active beats. resume() uses current time, not stale paused time.</done>
