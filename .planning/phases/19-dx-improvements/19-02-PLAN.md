  **DX-04: playTogether**

  Create `src/utils/play-together.ts`:
  ```typescript
  import type { Playable } from '@interfaces/playable'

  export async function playTogether(playables: Playable[]): Promise<void>
  ```

  Implementation:
  - Each Playable has `playAt(time: number)`. To sync them, capture a single `audioContext.currentTime` and add a tiny offset (e.g., +0.01s) to ensure all sources start at exactly the same timestamp.
  - Problem: playables don't expose their audioContext directly. But BaseSound has a public `audioContext` property. Use duck-typing: check if the first item has `audioContext`, use it. If none have it, just call `play()` on all (graceful fallback).
  - Better approach: Accept an optional AudioContext or import `getOrCreateAudioContext` from `src/audio-context.ts` (created in Plan 01).
  - Implementation:
    ```typescript
    export async function playTogether(playables: Playable[]): Promise<void> {
      if (playables.length === 0) return
      // Get audioContext from first playable that has it, or from shared context
      const ctx = (playables[0] as any).audioContext ?? getOrCreateAudioContext()
      const startTime = ctx.currentTime + 0.01 // tiny buffer for scheduling
      await Promise.all(playables.map(p => p.playAt(startTime)))
    }
    ```
  - Export from `src/index.ts`

  **DX-05: createSounds batch loader**

  Add to `src/index.ts`:
  ```typescript
  export async function createSounds(
    urls: string[],
    onProgress?: (loaded: number, total: number, url: string) => void
  ): Promise<Sound[]>
  ```

  Implementation:
  - Load each URL using the existing `load()` function
  - After each successful load, call `onProgress(loadedCount, total, url)` if provided
  - Use sequential loading (not Promise.all) so progress events fire in order and partial failures are reported immediately
  - Actually, parallel is faster. Use a counter approach: start all loads in parallel, increment counter as each resolves, call onProgress.
  - On partial failure: throw an AggregateError-style error that includes which URLs failed and which sounds succeeded. Or simpler: collect all results with Promise.allSettled, throw if any failed, return successes.
  - Return type: `Promise<Sound[]>`

  Tests:
  - Test playTogether calls playAt with same timestamp on all sounds
  - Test playTogether with empty array is a no-op
  - Test createSounds loads multiple URLs
  - Test createSounds fires progress events
  - Test createSounds handles partial failures

  **DX-08: Extensible ControlType**

  In `src/controllers/base-param-controller.ts`:
  - Currently: `export type ControlType = 'frequency' | 'gain' | 'detune' | 'pan'`
  - Change to use a mapped type with module augmentation support:

  ```typescript
  // Base control types provided by the library
  export interface ControlTypeMap {
    frequency: 'frequency'
    gain: 'gain'
    detune: 'detune'
    pan: 'pan'
  }

  // Union type derived from the map — extends when ControlTypeMap is augmented
  export type ControlType = ControlTypeMap[keyof ControlTypeMap]
  ```

  This allows downstream users to extend via module augmentation:
  ```typescript
  declare module 'ez-web-audio' {
    interface ControlTypeMap {
      customParam: 'customParam'
    }
  }
  ```

  The ControlType union automatically includes the new value. The runtime _update() switch-case won't handle custom types, but that's expected — users extending ControlType would also need to provide custom controller logic. Document this in a JSDoc comment.

  NOTE: Verify that changing from a simple union to a mapped type doesn't break any existing code. The resulting ControlType is still `'frequency' | 'gain' | 'detune' | 'pan'` — it's structurally identical.
