# Plan 58.1-01: GrainPlayer Hardening

## Objective

Fix three QC findings in GrainPlayer: overlap setter performance cliff (QC-1-03), setTimeout background-tab throttling (QC-1-11), and dead code in loop offset handling (QC-1-25).

## must_haves

- Overlap setter validates and clamps to prevent 1000+ grains/sec
- GrainPlayer uses WorkerTimer instead of setTimeout for background-tab resilience
- Dead code in loop offset handling is removed
- All existing GrainPlayer tests pass
- New tests cover overlap clamping behavior

## Tasks

<task id="1">
**Clamp overlap setter to prevent performance cliff (QC-1-03)**

The `overlap` setter at line 423 has no validation. When `overlap >= grainSize`, `getHopSize()` returns the floor of 0.001, meaning grains fire at ~1000/sec.

In `src/grain-player.ts`:

1. Update the `overlap` setter to clamp: `this._overlap = Math.max(0, Math.min(value, this._grainSize - 0.001))`. This ensures hop size is always at least 0.001s (1000 grains/sec hard cap), and overlap cannot exceed grainSize.

2. Also update the constructor line that sets `this._overlap` to use the same clamping logic (after `this._grainSize` is set).

3. Update the `grainSize` setter to re-clamp overlap when grainSize shrinks: after setting `this._grainSize`, add `this._overlap = Math.min(this._overlap, this._grainSize - 0.001)`.

4. Update the `overlap` JSDoc to document the clamping behavior.
</task>

<task id="2">
**Replace setTimeout with WorkerTimer (QC-1-11)**

GrainPlayer uses `setTimeout` for its scheduling loop (line 194), which gets throttled to ~1000ms in background tabs. WorkerTimer already exists and is used by Transport and BeatTrack.

In `src/grain-player.ts`:

1. Add import: `import { WorkerTimer } from '@utils/worker-timer'`

2. Replace the `timerId: ReturnType<typeof setTimeout> | null = null` field with `private timer: WorkerTimer | null = null`.

3. Remove the `SCHEDULE_INTERVAL` constant (WorkerTimer handles its own interval).

4. Update `scheduleLoop()`: Remove the `setTimeout` call at line 194. The method should only do the while-loop grain scheduling (lines 188-191). It no longer needs to call itself recursively.

5. Update `play()`: Create the WorkerTimer lazily and start it:
   ```
   if (!this.timer) this.timer = new WorkerTimer({ interval: this.SCHEDULE_INTERVAL })
   ```
   Wait — keep `SCHEDULE_INTERVAL = 25` as the WorkerTimer interval config. Then:
   ```
   this.timer.start(() => this.scheduleLoop())
   ```

6. Update `stop()`: Replace `clearTimeout(this.timerId)` with `this.timer?.stop()`.

7. Update `pause()`: Replace `clearTimeout(this.timerId)` with `this.timer?.stop()`.

8. Update `resume()`: Use `this.timer?.start(() => this.scheduleLoop())` instead of calling `scheduleLoop()` directly. Keep the `nextGrainTime` reset.

9. Update `dispose()`: Replace `clearTimeout(this.timerId)` with `this.timer?.dispose()` and set `this.timer = null`.
</task>

<task id="3">
**Remove dead code in loop offset handling (QC-1-25)**

In `scheduleGrain()`, lines 223-225:
```typescript
if (this._loop && offset > maxOffset) {
  offset = offset % this.buffer.duration
}
```

This is dead code because `offset` is already clamped to `maxOffset` on line 221:
```typescript
offset = Math.max(0, Math.min(offset, maxOffset))
```

So `offset > maxOffset` is always false. Remove lines 223-225 entirely (the `if` block and its body).
</task>

</task>
