### Fix LFO syncLifecycle multi-target bug (QC-1-04)

In `src/lfo.ts`, modify the `syncLifecycle` stop/end listeners (lines ~220-239) so they disconnect only the specific target rather than stopping the entire LFO.

**Current behavior:** `record.stopListener` calls `this.stop()` which kills the oscillator for ALL connections.

**New behavior:**
1. Stop listener calls `this.disconnect(target)` to remove only that target's connections
2. After disconnecting, check if any remaining connections exist
3. Only call `this.stop()` if no connections remain at all

Replace the stop/end listener logic:
```typescript
record.stopListener = (() => {
  // Disconnect only this target, not the entire LFO
  this.disconnect(target)
  // If no connections remain, stop the oscillator
  if (this._connections.length === 0 && this._isRunning) {
    this.stop()
  }
}) as EventListener
```

Also update the play listener to only start if not already running (already does this, just verify).

**Verify:** Existing LFO tests pass. Add test in task 3.
</task>

### Add JSDoc for BaseEffect disposal contract and LFO depth limitation (QC-1-14)

**BaseEffect** (`src/effects/base-effect.ts`):
Add to the `dispose()` method JSDoc:
```
Subclasses that create additional audio nodes (e.g., BiquadFilterNode, DynamicsCompressorNode)
MUST override dispose() to disconnect those nodes before calling super.dispose().
Pattern:
  public override dispose(): void {
    try { this.myNode.disconnect() } catch { /* already disconnected */ }
    super.dispose()
  }
```

**LFO** (`src/lfo.ts`):
Add JSDoc note to `LFOConnectOptions.depthUnit`:
```
Note: When depthUnit is 'ratio' or 'cents', depth is calculated from the parameter's
current value at connection time. If the parameter value changes later (e.g., gain is
adjusted), the modulation depth will NOT automatically update. Use 'absolute' for
fixed depth, or call disconnect()/connect() to recalculate.
```

Add similar note to `LFOConnectOptions.depth`:
```
Note: For 'ratio' and 'cents' depthUnit, this value is multiplied against the
target parameter's value at connection time. The resulting absolute depth is fixed
for the lifetime of the connection.
```
