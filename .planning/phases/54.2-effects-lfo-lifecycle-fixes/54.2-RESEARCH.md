# Phase 54.2: Effects & LFO Lifecycle Fixes — Research

**Researched:** 2026-03-07
**Status:** Complete

## QC Findings Analysis

### QC-1-04 (High): LFO syncLifecycle stops ALL connections when one target stops

**Problem:** When `syncLifecycle: true` is used to connect an LFO to multiple targets, the stop/end listener calls `this.stop()` which stops the entire oscillator node — killing modulation for ALL connected targets, not just the one that stopped.

**Location:** `src/lfo.ts` lines 220-239

**Current code (simplified):**
```typescript
record.stopListener = (() => {
  if (this._isRunning) {
    this.stop()  // ← BUG: stops the entire LFO oscillator
  }
}) as EventListener
```

**Fix:** Instead of stopping the entire LFO, the stop/end listener should disconnect only the specific connection for that target. If all syncLifecycle connections are disconnected, then stop the oscillator.

**Approach:**
- Stop listener should call `this.disconnect(target)` to remove only that target's connections
- After disconnecting, check if any remaining connections have `syncLifecycle: true`
- Only call `this.stop()` if no syncLifecycle connections remain AND no non-syncLifecycle connections exist
- If non-syncLifecycle connections remain, keep running (user manages those manually)

### QC-1-13 (Medium): Missing dispose() for 4 effect subclasses

**Problem:** CompressorEffect, DistortionEffect, EQEffect, and FilterEffect do not override `dispose()`. While BaseEffect.dispose() disconnects inputNode, outputNode, dryGain, wetGain, each subclass creates additional internal nodes that won't be disconnected.

**Affected nodes:**
- CompressorEffect: `compressorNode` (DynamicsCompressorNode)
- DistortionEffect: `waveShaperNode` (WaveShaperNode), `toneFilter` (BiquadFilterNode)
- EQEffect: `lowFilter`, `midFilter`, `highFilter` (3x BiquadFilterNode)
- FilterEffect: `filterNode` (BiquadFilterNode)

**Pattern to follow:** DelayEffect and ReverbEffect already have correct `dispose()` overrides:
```typescript
public override dispose(): void {
  try { this.delayNode.disconnect() } catch { /* already disconnected */ }
  try { this.feedbackGain.disconnect() } catch { /* already disconnected */ }
  super.dispose()
}
```

### QC-1-14 (Medium): LFO depth baked at connection time (docs fix)

**Problem:** When `depthUnit` is `'ratio'` or `'cents'`, the depth is calculated from `audioParam.value` at the time of `connect()`. If the underlying parameter value changes later, the depth won't adjust automatically.

**Location:** `src/lfo.ts` `_calculateDepth()` method (lines 503-526)

**Fix:** Add JSDoc to `LFOConnectOptions.depth` and `LFOConnectOptions.depthUnit` explaining this limitation. Also document in the main LFO class JSDoc.
