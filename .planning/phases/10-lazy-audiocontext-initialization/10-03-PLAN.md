  <action>
For each Vue component file that imports/calls initAudio():

1. Remove `initAudio` from the import statement. If `initAudio` is the only import, remove the entire import line. If it's destructured with other imports, remove just `initAudio` from the destructuring.

2. Remove the `await initAudio()` or `await lib.initAudio()` call. The factory functions (createSound, createOscillator, createBeatTrack, etc.) now handle AudioContext creation internally.

3. Verify the surrounding code still makes sense — the `await` on factory functions is sufficient for initialization.

Specific patterns to handle:

**Pattern A** (destructured import): Files like DrumMachine.vue, OscillatorDemo.vue, TrackDemo.vue
```javascript
// BEFORE
const { initAudio, createBeatTrack } = await import('ez-web-audio')
await initAudio()
// AFTER
const { createBeatTrack } = await import('ez-web-audio')
```

**Pattern B** (lib.initAudio): Files like AudioDemo.vue, FilterDemo.vue, SynthDrumKit.vue, etc.
```javascript
// BEFORE
const lib = await import('ez-web-audio')
await lib.initAudio()
// AFTER
const lib = await import('ez-web-audio')
// (just remove the initAudio line)
```

**Pattern C** (separate initAudio import): Files like SynthKeyboard.vue
```javascript
// BEFORE
const { initAudio } = await import('ez-web-audio')
await initAudio()
// AFTER
// (remove both lines entirely)
```

Do NOT remove the dynamic `import('ez-web-audio')` itself — only the initAudio import/call.
