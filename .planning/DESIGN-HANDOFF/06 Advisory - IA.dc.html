Information architecture — tips, not mandates

The VitePress frame stays. These are adopt-selectively suggestions for how demo pages organize prose, code, and the interactive component — plus sidebar sequencing, naming, and onboarding. Nothing here blocks the component specs; skip any of it freely.

A · Demo-page template

Component first, then "how", then code

Today most pages open with prose and bury the live demo. Invert it: the thing that sells the library is touching it. Lead with the component (Hard Constraint #5 — it's already live, no load button), state the one-line takeaway right under it, then explain, then show the code the reader now wants.
