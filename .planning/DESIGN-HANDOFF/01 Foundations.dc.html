Foundations

The design language and shared element system for the EZ Web Audio demos. Every one of the 22 demos plus the Groovebox is assembled from the tokens and parts on this page. Design the part once; it lands everywhere.

§1 · Signature accent

A "Signal" accent — one voice for interaction

The library needs a hue that reads as audio — a lit LED, a live signal — not a generic docs blue. It carries every primary action, playhead, focus ring, and "playing" state. Three candidates below; Signal green is the recommendation. It's set as --vp-c-brand-1 so it also tints VitePress links and buttons, unifying docs + demos.

§2 · Sound palette

Six voices for lanes, tracks & waveforms

The signal-green accent means "the app is talking to you." The sound palette means "this is a distinct sound source." Equal chroma and lightness, hue-stepped so no lane out-shouts another — and re-tuned brighter for dark mode. Canvas visualizers read these from CSS vars at draw time (Hard Constraint #2): getComputedStyle(el).getPropertyValue('--ewa-kick') — never a hardcoded hex.

§3 · Tokens → VitePress vars

Mapped to the theme, not invented alongside it

Wherever VitePress already owns a color role, we alias to it so the demos track the docs theme (and any future re-skin) for free. New roles (accent variants, the sound palette) are the only additions — declared once in the theme with light + dark values.
