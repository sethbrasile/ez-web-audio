## Execution Methodology (binding for all M8 plans)

### Roles

- **Orchestrator (Opus):** one session per phase. Reads `M8-PLAYBOOK.md` + the phase `PLAN.md`. Dispatches one subagent per task. Reviews every diff before commit. Runs gates. Updates STATE.md/ROADMAP.md/SUMMARY.md.
- **Implementer (Sonnet):** all code tasks. Receives a self-contained task brief — exact files, current-state summary, acceptance criteria, verification command. Never sees the whole plan.
- **Mechanical (Haiku):** only zero-judgment tasks explicitly marked `model: haiku` in plans (file moves, config find/replace).

### Review loop (per task)

1. Implementer returns diff.
2. Orchestrator checks diff against acceptance criteria; runs the task's verification command (scoped typecheck/tests).
3. Fail → reject with specific feedback. Max 2 retries, then orchestrator implements the task itself.
4. Pass → commit (repo commit conventions; one commit per task; `Co-Authored-By` trailer).

### Gates

- **Per-phase exit gate:** `pnpm typecheck` + `pnpm lint` + `pnpm test` + E2E suite all green; phase `VERIFICATION.md` written (goal-backward: does the codebase deliver what the phase promised).
- **Human gates (only these four):**
  1. Design brief handoff → Seth takes `DESIGN-BRIEF.md` to claude-design, returns handoff packet (blocks 74-02+ and 76 UI work only).
  2. Listening checkpoint after Phase 75 (~15 min; blocks 76).
  3. Full UAT after 77 (blocks 78).
  4. npm org creation + publish approval (Phase 78).
- Anything else that seems to need a human decision: orchestrator writes it to `.planning/M8-QUESTIONS.md` with its own recommendation, takes the recommendation, moves on. Seth reviews the file at gates.

## Phase 72 — Workspace + `@ez-web-audio/vue`

**Conversion:** pnpm workspace. `packages/core` (current `src/` moves; npm name `ez-web-audio` unchanged), `packages/vue`, `packages/react` (stub only — README + package.json, no code). Docs stays at `/docs`, consumes workspace packages via workspace protocol + aliases. Root scripts keep working (`pnpm dev`, `pnpm test`, `pnpm build`). CI publish workflow updated for version-locked multi-package publish on `v*` tags. TypeDoc, Vitest, Playwright, ESLint configs updated for new paths.

**`@ez-web-audio/vue` composables** (extracted from proven demo patterns; SSR-safe — VitePress SSR renders them; no AudioContext creation until user interaction):

- `useAudioContext()` — lazy init state: `{ ready, init() }`.
- `useCleanup()` — register disposables; auto `dispose()`/`stop()` on `onUnmounted`. Kills the deep-review structural patterns (demo-resource-cleanup-inconsistency, demo-audio-init-duplication).
- Factory wrappers: `useSound`, `useTrack`, `useOscillator`, `useBeatTrack`, `usePolySynth`, `useGrainPlayer`, `useLFO`, `useTransport`. Uniform shape: `{ instance: ShallowRef<T | null>, loading: Ref<boolean>, error: Ref<Error | null>, load(): Promise<T> }`. Lazy: `load()` triggered by first user interaction, idempotent.
- `useBeatTrack` wires existing `wrapWith: reactive` pattern for beat reactivity.

Peer-dep on `ez-web-audio` + `vue`. Unit tests: happy-dom + existing `standardized-audio-context-mock` pattern; TDD (test first per composable).

## Phase 75 — Sound quality

- Shared demo master-bus util with limiter (DynamicsCompressor-based brickwall-ish settings). Demo-level util in docs theme, NOT library API (promote later if proven).
- Gain staging per demo. Objective verification: offline-render analysis script (OfflineAudioContext render → assert zero clipped samples; peak/RMS within documented windows) run in CI or via Playwright.
- Preset retuning against documented music-production references (e.g., vibrato 5–7 Hz / ±25–50 cents; tremolo depth reaching near-silence; wah bandpass Q 4–8). Deep review 2026-03-19 already fixed correctness — this pass optimizes for "sounds great in first 5 seconds."
- **Existing repo assets only.** Subagents must NOT source new samples (licensing risk). Asset wishlist → `M8-QUESTIONS.md` for Seth.
- **Exit: human listening checkpoint** (~15 min, all demos). Findings become fix tasks before Phase 76 starts.

## Phase 76 — Groovebox showcase

The announcement centerpiece. Built on `@ez-web-audio/vue` + Transport/Sequencer + Phase 75 master bus. UI per claude-design handoff packet.

- **Lanes:** 4 drums (kick/snare/hihat/clap — existing samples) + bass synth (16-step pitch row, waveform select) + lead arp (pattern presets, not per-step editing).
- **Sequencing:** 16 steps × 2 bars, BPM slider, swing control, per-lane mute/solo.
- **FX:** master delay + reverb sends with minimal controls.
- **Presets:** 3–4 curated patterns (Phase 75 quality bar).
- **Share:** URL-shareable state — base64 JSON in location hash; loading a shared URL restores full state.
- **Homepage hero:** compact variant embedded on docs homepage.
- Dedicated E2E suite. Serves as binding stress test — friction files back as core/binding issues.
